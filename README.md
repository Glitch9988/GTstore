## المميزات

### أوضاع اللعب

| الوضع | الوصف | يحتاج إنترنت؟ |
|---|---|---|
| **لعب فردي** | 10 أسئلة (قابل للتعديل)، فئة وصعوبة ووقت تختارهم بنفسك | لا |
| **ضد البوتات** | مباراة كاملة ضد 3 بوتات بشخصيات وأسماء مختلفة | لا |
| **تحدي الأصدقاء** | غرفة بكود من 5 حروف، من 2 لـ 8 لاعبين، من أي موبايل | نعم |

### تجربة اللعب

- **200 سؤال أصلي** في 8 فئات، 25 سؤال لكل فئة.
- **3 مستويات صعوبة** (سهل / متوسط / صعب) ووقت لكل سؤال (15 / 20 / 30 ثانية).
- **نقاط عادلة:** أساس حسب الصعوبة + بونص سرعة + بونص سلسلة إجابات + بونص أول إجابة صحيحة.
- **توضيح قصير** بعد كل سؤال عشان تتعلم حاجة جديدة.
- **وسائل مساعدة** في اللعب الفردي: حذف إجابتين، وتخطي السؤال (مرة واحدة لكل مباراة).
- **تفاعلات مباشرة** في الأونلاين (🍆 👏 😱 🔥 😂) بتظهر لكل اللاعبين.
- **لوحة صدارة أونلاين** محفوظة على السيرفر.
- **إحصائيات محلية:** أعلى نتيجة، أطول سلسلة، دقة الإجابات، عدد المباريات.

### التصميم

- واجهة **RTL** كاملة بخط **Tajawal**.
- لوحة ألوان 2026: بنفسجي عميق + ليموني + ماجنتا، مع تدرجات وتأثيرات زجاجية.
- **شخصية البتنجانة** مرسومة بالكود (Compose Canvas) بـ 5 حالات مزاجية.
- **20 شخصية لاعب** مرسومة بالكود (شكل، شعر، لحية، نظارة، خلفية).
- **أيقونة لانشر** احترافية مولّدة بالكود (legacy + adaptive).
- مؤثرات صوتية وهبتيك أصلية 100% (مولّدة برمجيًا).

## بناء التطبيق من المصدر

### المتطلبات

- **JDK 17** (مثل Temurin أو Oracle JDK 17).
- **Android SDK** فيه:
  - Platform 36
  - Build-Tools 36.x
  - Platform-Tools
- **Gradle 8.13** (أو استخدم الـ wrapper لو موجود).
- اتصال إنترنت أول مرة لتحميل الاعتماديات.

### الخطوات (Windows)

```powershell
$env:JAVA_HOME = "C:\Program Files\Java\jdk-17"
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"

# من جوه مجلد المشروع
gradle :app:assembleRelease --console=plain --no-daemon
```

الناتج:

```
app/build/outputs/apk/release/app-release.apk
```

> **ملاحظة:** لو ظهرت رسالة `NativeCommandError` في PowerShell فهي مجرد تحذير من
> خروج Gradle على stderr — المهم وجود `BUILD SUCCESSFUL` في آخر المخرجات.

### بناء نسخة تجريبية (debug)

```powershell
gradle :app:assembleDebug --console=plain --no-daemon
```

### مشاكل شائعة

| المشكلة | الحل |
|---|---|
| `Could not connect to Kotlin compile daemon` | المشروع مضبوط على `kotlin.compiler.execution.strategy=in-process` في `gradle.properties` |
| `SDK location not found` | أنشئ `local.properties` فيه `sdk.dir=C\:\\path\\to\\Android\\Sdk` |
| فشل تحميل الاعتماديات | تأكد من الإنترنت، أو اضبط بروكسي Gradle في `~/.gradle/gradle.properties` |

## تشغيل سيرفر الأونلاين

السيرفر مكتوب بـ **Node.js + Express + Socket.IO**، وبيحفظ البيانات في ملف JSON —
مش محتاج Firebase ولا قاعدة بيانات خارجية.

### التشغيل محليًا

```powershell
cd server
npm install
npm start
```

هتلاقي:

```
X البتنجان — سيرفر اللعب شغّال
http://localhost:3000
الأسئلة: 200 سؤال في 8 فئات
```

اختبار سريع:

```powershell
curl http://localhost:3000/health
```

### اللعب على نفس شبكة الواي فاي

1. شغّل السيرفر على الكمبيوتر.
2. اعرف IP الكمبيوتر:
   ```powershell
   ipconfig
   ```
   مثال: `192.168.1.5`
3. اسمح للبورت 3000 في جدار الحماية (Windows Defender Firewall → Inbound Rules).
4. في التطبيق: **تحدي الأصدقاء** → اكتب `http://192.168.1.5:3000` → **احفظ العنوان**.
5. اعمل غرفة وابعت الكود لأصحابك — كلهم بيدخلوا نفس العنوان.

> على محاكي أندرويد، عنوان الكمبيوتر هو `http://10.0.2.2:3000`.

### النشر على استضافة مجانية/مدفوعة

**Render (الأسهل):**

1. ارفع المشروع على GitHub.
2. في Render: **New → Blueprint** واختار ملف `server/render.yaml`.
3. Render هينشر السيرفر ويبعتلك رابط HTTPS جاهز.
4. حط الرابط في التطبيق.

> الخطة المجانية بتنام بعد فترة خمول، فأول اتصال ممكن ياخد ثواني.
> بيانات اللاعبين بتتحفظ في `server/data/db.json` — استخدم Disk دائم لو عايزها تفضل.

**Docker (أي VPS):**

```powershell
cd server
docker build -t batengan-server .
docker run -d --name batengan -p 3000:3000 -v batengan-data:/app/data batengan-server
```

**ملاحظة HTTPS:** التطبيق بيسمح بـ `http://` للأجهزة المحلية، لكن لو هتستخدم استضافة
عامة استخدم **HTTPS** (زي ما Render بيدي بالظبط).

## اللعب أونلاين خطوة بخطوة

1. **صاحب الغرفة:**
   - يفتح **تحدي الأصدقاء**.
   - يحط عنوان السيرفر ويحفظه.
   - يختار الفئة وعدد الأسئلة والوقت.
   - يضغط **اعمل الغرفة** ويبعت الكود (مثال: `6HGJR`).

2. **الأصدقاء:**
   - يفتحوا نفس الشاشة.
   - يحطوا نفس عنوان السيرفر.
   - يكتبوا الكود ويضغطوا **دخول الغرفة**.
   - يضغطوا **جاهز**.

3. **البداية:**
   - صاحب الغرفة يضغط **ابدأ المباراة** لما الكل يجهز.
   - السيرفر هو اللي بيختار الأسئلة ويحسب الوقت والنقاط — مفيش غش من التطبيق.
   - بعد كل سؤال بتظهر الإجابة الصح والتوضيح، وبعدها السؤال اللي بعده تلقائيًا.

4. **بعد المباراة:**
   - ترتيب نهائي للجميع.
   - **ريماتش** بنفس الغرفة.
   - النتيجة بتتسجل في لوحة الصدارة.

> لو اللاعب قفل التطبيق ورجع في نفس المباراة، السيرفر بيرجّعه للغرفة تلقائيًا
> على طول ما الجلسة لسه شغالة.

## بنك الأسئلة

- **المسار:** `content/questions.json` (المصدر) و `app/src/main/assets/questions.json` (النسخة اللي في التطبيق).
- **الصيغة:**

```json
{
  "id": "geo-01",
  "cat": "جغرافيا",
  "diff": 1,
  "q": "إيه أطول نهر في العالم؟",
  "a": "النيل",
  "d": ["الأمازون", "المسيسيبي", "اليانجتسي"],
  "e": "النيل بيتقاسمه 11 دولة وطوله حوالي 6650 كم."
}
```

- `d` فيه **3 إجابات غلط** دائمًا.
- التطبيق بيلخبط ترتيب الاختيارات باستخدام `id.hashCode()` عشان الترتيب يبقى ثابت
  للاعب الواحد ومختلف بين اللاعبين.
- للتحقق من الملف:

```powershell
node tools/check-questions.js
```

بيتأكد من: العدد، توزيع الفئات، عدم تكرار الـ id، وجود 3 اختيارات مختلفة، ووجود توضيح.

> لو أضفت أسئلة جديدة، انسخ الملف لـ `app/src/main/assets/` و`server/data/` أو شغّل
> الأمر اللي في `docs/BUILD_AND_SIGN.md`.

## طريقة الحساب

المعادلة متطابقة في التطبيق (`Scoring.kt`) والسيرفر (`scoring.js`):

```
نقاط الإجابة الصحيحة =
   100                          (الأساس)
 + (الصعوبة - 1) × 25           (easy=0، medium=25، hard=50)
 + round(100 × الوقت المتبقي / الوقت الكلي)
 + min(السلسلة, 4) × 15
 + 40                          (لو أول واحد يجيب صح — أونلاين فقط)
```

- الإجابة الغلط = **0 نقطة** مع تصفير السلسلة.
- الترتيب النهائي: النقاط ← عدد الإجابات الصح ← الاسم (لضمان ترتيب ثابت).

## الاختبارات

### اختبارات السيرفر

```powershell
cd server
npm test
```

بتغطي:

- حساب النقاط والترتيب.
- تحميل بنك الأسئلة وفلترة الفئات والخلط.
- دورة حياة الغرفة: الجاهزية، بدء المباراة، الإجابات، الكشف، نهاية المباراة، الريماتش.
- نقل الاستضافة عند خروج صاحب الغرفة.
- خصوصية `room:state` لكل لاعب (`myId`).

### اختبار يدوي للأونلاين

بعد ما تعمل غرفة من التطبيق، تقدر تدخل لاعب تاني من الكمبيوتر:

```powershell
node tools/online-test-player.js <CODE> http://127.0.0.1:3000
```

اللاعب التجريبي بيدخل الغرفة، يجهّز، ويجاوب عشوائيًا — مفيد للتأكد إن السيرفر شغال
من غير ما تفتح موبايل تاني.
